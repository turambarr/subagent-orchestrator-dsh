# 实验编排 SOP

> **pro 管"做什么、为什么、算不算通过"；flash 管"照着做、把结果原样带回来"。**
> 本技能把这条线写成可复用机制：什么时候拆、拆给谁、怎么下指令、怎么验收。

## 核心循环

```
用户: 目标 + 粗验收标准
   ↓
pro:  起草【分解计划】—— 子任务清单 / 每个的模型 / 验收基准 / 依赖顺序
   ↓
用户: 确认 / 修改计划      ←—— 闸门：不确认不派工
   ↓
pro:  逐条派工 flash（按计划）
   ↓
flash: 回报【事实 + 与基准差值】
   ↓
pro:  判读 + 裁决 → 下一轮 或 结束
```

顶层控制被显式化成一个可审查的【分解计划】文档，而不是藏在 pro 脑子里：用户在派工前就能看到并修改每一步。

## 唯一硬规则（拆解判据）

一个子任务能拆给 flash，当且仅当**同时**满足两条：

1. **可执行**：有已知命令 / 脚本 / 文件路径，过程确定，不需要临场发明。
2. **可验收**：派工前就能写下一个"基准数字 + 容差"，flash 只需比大小。

缺一条就不拆，留在 pro。口诀：答案"查得到 / 跑得出 / 比得大小"就拆；答案需要"为什么 / 对不对 / 怎么办"就不拆。

## 形状菜单（参考清单，非约束）

常见可拆形状，供 pro 起草计划时提示，可增删：

| 形状 | 做什么 | 产出 |
|---|---|---|
| 采集 | 读文件 / grep / 列目录 | "存在什么" |
| 执行 | 跑已知命令 / 脚本 | "运行结果" |
| 校验 | 测量值 vs 基准比大小 | "差多少" |
| 审查 | 只读 grep 措辞 / 注释 / 文档 | "命中清单" |
| 转换 | 机械格式转换（如 md→docx） | "文件" |

## 模型映射

| 层 | 模型 | 职责 | 产出 |
|---|---|---|---|
| 顶层控制 | pro | 目标、假设、验收标准、裁决、改架构 | 结论 + 下一步 |
| 执行 | flash | 采集、执行、校验、审查、转换 | 事实 + 差值 |

**结论与决策永远由 pro 产出；flash 产出止于事实与差值。** 判读步骤在分解计划里固定标 `pro`，不放进 flash 列。

## 分解计划

每实验一次，pro 起草、用户确认后生效。模板见 `prompt-templates/plan.md`。骨架：

```
## 实验分解计划（#E<n>：<一句话目标>）
目标：<要验证/证明什么>
粗验收：<顶层判据>

| # | 子任务 | 形状 | 模型 | 验收基准(数字+容差) | 依赖 |
|---|---|---|---|---|---|
| 1 | ... | 采集 | flash | ... | 无 |
| ... | 判读：... | — | pro | 见 acceptance/gates.md | 2,3 |

用户确认：□ 按此执行  □ 修改第 _ 步
```

## flash 派工 prompt

每条 flash 任务必须**自包含**（flash 不共享 pro 上下文）。五类骨架见 `prompt-templates/`，共同结构：

```
【角色】你是一次性实验执行员：只做、只报、不判断、不自行改方案。
【环境】<别名/路径/解释器/工作目录>
【任务】一句话：做什么。
【步骤】1..n 条精确命令。
【验收基准】派工前定死的数字 + 容差；不达标 = 原样报告，不要修。
【回报格式】任务 / 方法 / 结果(原始输出摘录) / 与基准差值 / 偏差说明 / 未决。
【红线】失败重试 2 次后原样报告；只报测量值和差值，禁写结论；输出零/异常时报告现象，禁猜原因兜底。
```

## 验收

两层验收 + 四级门 + 三条红线，见 `acceptance/gates.md`。

- flash 级（任务层）：执行完成？数字进容差？六段回报齐？→ 差一项打回，不进入结论。
- pro 级（实验层）：结果支持/否定哪个假设？改参 / 换假设 / 结论成立？
